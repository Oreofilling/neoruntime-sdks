四三条贯穿性语义（读图要点）

① overlay 画在路由之前

一旦检测内容在总线话题上，帧在进入 FrameRouter 之前就已带框——RTSP、录像（编码支路）和 FdMediaClient 拿到的原始帧都带标注（auto_feed 与手动编码同样带）；overlay 只烘在 ai_overlay.stream_map 配置为目标流的流上，需要"干净帧 + 自己画"的应用应订阅未被映射的流。

② 同一 socket、平级租户

camera.sock 既是原始帧发布口（fd 协议）也是 DSP 缓冲管理口（PLAT-5）；ai-runtime 与 SDK 的 FdMediaClient 是平级客户端，各自独立计"未还 ≤3、200ms 看门狗"配额，互不挤占。

③ 像素只在三处跨进程

fd 协议（mmap 直达 dma-buf）、编码流（Annex-B 字节）、DSP 缓冲面（fd + gRPC）。SDK 的零拷贝链（keep-fd → DSP resize → encode_jpeg_hw）就是让像素在这三处尽量不出 daemon。

五用户视角：每条数据流向能为你做什么

数据流出口用户获得的功能典型场景
RTSP rtsp://<ip>:8554/<stream>任何标准播放器 / NVR 直接看直播，无需写一行代码快速验机、接入存量监控（VLC / ffplay / ONVIF）
camera.sock 原始帧（FdMediaClient）实时 NV12 原始像素（主 / 子码流），自研 AI 分析、抓图、自绘 UI；keep-fd 零拷贝省内存与拷贝 CPU自己跑模型 / 算法
encoded/<stream>.sock（EncodedStreamClient）TS 单文件录像、HLS 网页直播（关键帧切片、m3u8 原子替换）、事件前 N 秒预录环录像回放、web 直播、事件剪辑
encoded/audio_capture.sock（AudioStreamClient）拾音器音频帧（30B 头启发式兼容当前视频布局头）音频分析、对讲采集端
ai-runtime.sock StreamInfer（InferenceClient）订阅平台自动推理结果——自己不跑模型、零像素传输轻客户端联动
event-bus.sock（EventClient）跨应用订阅推理 / 事件话题（通配、每订阅者独立队列）多应用扇出、告警联动
overlay（UpdateAiOverlay 配置 + annotate 内容）编码流 / RTSP / 录像直接带检测框 + 标签，或人脸马赛克 / 模糊（隐私合规）标注即所见、隐私脱敏
DSP 缓冲面 + 任务面（DspClient / accel）resize / crop / convert / blend / JPEG 硬件加速，CPU 近零占用；numpy 自动兜底、health() 可观测预处理卸载、高并发抓图
